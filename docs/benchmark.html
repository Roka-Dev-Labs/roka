Benchmark

MVP study: the shipped MCP prune_file tool on the LogHub corpus. 15 real production log sources, one 4,000-character budget, no per-file tuning.

MetricResult
Avg. lines removed92.2%
Avg. compression~69× (chars in → 4K out)
Sources with real errors still surfaced11 / 11

What this measures

Retention under budget — did a real error line survive a 4,000-character pack? It proves compression and error retention. It does not prove the tool finds the right evidence for arbitrary questions, or that agents debug better with the slice.

Full methodology, Thunderbird before/after, and explicit non-claims: research.html. Per-dataset table: testing.html.
